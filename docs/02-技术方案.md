# MacRight 技术方案

状态：首版实现已完成，关键系统交互的实机验收进行中。更新日期：2026-10-29。

依据：[产品方案](01-产品方案.md)。参考基线为 MacNewFile 本地提交 `9fd2a1b4a18d606701bd57fd8acca94c26b6268d`。

## 1. 技术结论

采用 Swift 主应用、Finder Sync 扩展和按需启动的终端启动器。主应用使用 SwiftUI 展示设置；扩展使用 AppKit 构建菜单，负责文件创建、复制路径与定位文件；启动器通过 NSWorkspace 打开所选终端，完成后退出。

实现采用模板化、明确目标目录、统一非覆盖写入和显式错误处理。后台组件统一执行文件创建与终端打开，不使用 AppleScript → Shell → XML 拼接链。签名沙盒发送端与已安装后台组件已验证五种文件创建和原生终端调用；受保护目录的系统权限复用仍待用户实测。

## 2. 参考实现问题与环境约束

| 当前事实 | 设计处理 |
| --- | --- |
| `FinderSync.m` 同时承担菜单、挂载卷发现、剪贴板、脚本和八类文件创建 | 按上下文解析、文件创建、权限和系统集成拆分职责 |
| Office 通过手工 XML、zip 命令生成 | 直接复制三个内置 Office 模板 |
| 路径只做部分 Shell 转义后再嵌入 AppleScript | 文件操作全程传 URL，不构造可执行命令文本 |
| 先判断文件存在再写入，存在竞争窗口 | 实际创建必须拒绝覆盖；遇到名称占用才尝试下一名称 |
| 每 3 秒扫描挂载卷；注释称通知不可靠，但未见验证记录 | 先验证事件监听和扩展生命周期，不能直接认定替换定时器后一定有效 |
| 启动调用 `pluginkit` 并自动注册登录项；退出时停用扩展 | 主应用仅展示状态和系统管理入口，不自动改用户启停选择 |
| 扩展配置全文件系统临时读写例外，错误主要输出日志 | 由统一后台组件执行目录操作，系统隐私权限和实际写权限分别检查 |
| README 声称 Finder Sync 已完全移除，并提到设置功能 | Apple 仍提供 Finder Sync 文档；当前代码未见对应设置页，不照搬这些说法 |
| 当前机器为 Apple Silicon，仅有 Command Line Tools 和 Swift 6.4 | 主应用与扩展已可用 Command Line Tools 完整构建，不依赖旧应用编译资源 |

Apple 将 Finder Sync 定位为文件同步集成，并明确说明它并非通用 Finder 界面扩展机制。为实现桌面/目录空白处右键，首版沿用该入口，但不据此承诺 App Store 审核、所有云盘或所有 Finder 视图均受支持。[来源 1]

## 3. 职责与状态所有权

| 组成 | 职责与持有状态 |
| --- | --- |
| `MacRightApp` | SwiftUI 状态窗口；读取扩展启用状态，打开系统扩展管理；不承担日常文件操作 |
| `FinderExtension` | 同步 Objective-C 回调适配和主线程菜单控制器；只在有效回调中读取上下文 |
| `FinderContextResolver` | 将本次右键位置和选中 URL 转为复制对象与唯一目标目录；不做磁盘写入 |
| `FileCreationService` | 文件类型到资源映射、非覆盖写入、返回新文件 URL；不读取 Finder 全局状态 |
| `SystemActions` | 剪贴板、Finder 定位、错误提示，将终端目录请求交给启动器 |
| `TerminalLauncher` | 以同一签名身份执行文件创建与终端打开；模板随组件打包，完成后退出 |
| `VolumeMonitor` | 维护用于显示菜单的目录集合；挂载信息与目录写入权限分开处理 |

上述职责作为普通 Swift 类型实现。主应用与终端启动器通过主应用偏好域共享终端选择，不增加 App Group、XPC 服务、数据库或常驻辅助进程。Finder 与文件打开/保存窗口可能各自启动扩展实例，因此全局单例或 actor 只能解决进程内同步。[来源 1]

## 5. 关键设计

### 5.1 右键上下文

构建菜单时捕获 URL 与菜单类型，动作点击时形成不可变的操作上下文；进入异步处理后不重新读取可能变化的 Finder 选区。执行前只复核目录存在和操作权限。[来源 1]

| 右键场景 | 复制路径对象 | 新建文件 / Terminal 目标 |
| --- | --- | --- |
| 目录或桌面空白处 | 当前目录 | 当前目录 |
| 单个普通文件夹 | 文件夹本身 | 文件夹内部 |
| 单个文件 | 文件本身 | 文件所在目录 |
| 多选项目 | Finder 返回的全部选中 URL，每行一个 | 选中项属于同一个父目录时使用该父目录；否则不提供这两项操作 |
| 侧边栏普通目录 | 该目录 | 该目录 |
| 搜索、虚拟节点或无有效目标 | 仅在存在真实选中项时允许复制 | 不能明确唯一目录时不提供 |

应用包及文档包按文件处理，不能因底层是目录而在包内创建新文件。复制路径保留 Finder 提供的路径语义；写入和权限判断单独处理符号链接与真实目录，避免字符串前缀判断目录归属。

### 5.2 模板与命名

| 类型值（业务含义） | 扩展名 | 内容来源 |
| --- | --- | --- |
| `text`（文本文件） | txt | 空内容 |
| `markdown`（Markdown 文档） | md | 空内容 |
| `word`（Word 文档） | docx | `Resources/Templates/Office/Blank.docx` |
| `excel`（Excel 工作簿） | xlsx | `Resources/Templates/Office/Blank.xlsx` |
| `powerPoint`（PowerPoint 演示文稿） | pptx | `Resources/Templates/Office/Blank.pptx` |

模板在构建时复制进后台组件 bundle，按固定枚举映射读取。资源缺失返回明确错误，不能退化为同扩展名的空文件。仓库模板的来源、清理范围和 SHA-256 见[资源说明](../Resources/README.md)及 [manifest](../Resources/Templates/manifest.json)。运行时不解析或改写 Office XML。

统一默认名采用本地化“未命名”/`Untitled`，依次尝试 `未命名.docx`、`未命名 (1).docx` 等。使用 `O_CREAT | O_EXCL` 排他创建，再写入空内容或模板字节；只有“目标已存在”错误进入下一名称，其余错误立即返回。不能使用先检查存在再允许覆盖的写法。跨进程的竞争由文件系统的排他创建保证，不能仅靠进程内 actor。

写入成功返回 URL 后再请求 Finder 选中。写入前记录文件设备与 inode，写入或关闭报错后核对当前路径身份，只处理可证明属于本次操作的残留，不能误删先前存在或被替换的文件；可清理的残留移至废纸篓，无法清理则明确告知位置。成功创建但 Finder 定位失败时提示“文件已创建”，不得重新创建一份。

### 5.3 访问权限

菜单可见范围与磁盘写入权限是两件事，监控 `/` 不等于得到根目录读写授权。

Finder 扩展保留 App Sandbox，职责是获取菜单上下文并发送目录动作。文件创建与终端打开由随应用打包的同一后台组件执行，使用相同 Bundle ID 和证书签名身份。新建文件直接传入 Finder 目标目录，统一使用系统目录访问权限。

macOS 负责桌面、文稿等受保护位置的访问提示。每个受保护位置分别保留系统决定；文件系统的写权限、只读卷和 ACL 继续由实际写入操作检查。终端应用自身的隐私权限由该终端管理。

旧版自定义目录选择与书签读写流程已移除。已有用户书签数据保留原位，当前运行流程使用系统权限。[来源 2]

### 5.4 Terminal、卷变化与运行生命周期

- “在此打开终端”通过 `DirectoryActionRequest` 将目录编码为自定义 URL，交给随应用打包的 `TerminalLauncher`。启动器校验请求，读取终端偏好，以 NSWorkspace 向精确应用路径打开目录，完成后退出。终端操作直接使用 Finder 本次目标，新建请求携带固定 FileKind 枚举，在同一组件中复制内置模板并定位结果。路径始终作为数据传递。[来源 3]

- Finder 菜单动作方法由主扩展类实现，再同步转交主线程控制器。通过菜单项的数字 tag 查找创建菜单时的动作快照；复制动作直接携带 URL 列表，终端动作携带目录，新建动作携带文件类型与目录，不传输自定义 representedObject。内存中最多保存最近 256 个动作；过期动作提示重新打开菜单，不读取新选区替代旧目标。
- 卷集合初始化时读取挂载卷，监听挂载、卸载、改名及唤醒事件，监控集合变化时更新 Finder。监控系统根目录和挂载卷的父目录（例如 `/Volumes`），通过子目录覆盖卷内右键操作。Finder 会将监控根目录的侧边栏图标替换为应用图标，因此挂载卷本身作为子目录覆盖，保留各卷原有图标。
- 扩展由系统托管，关闭最后一个主窗口即退出主应用，不保留指引进程；退出不调用 `pluginkit ignore`。主应用使用公开的状态和管理 API，不直接操作用户的扩展开关，不自动添加登录项。[来源 4]
- 主线程负责 UI 和菜单；文件 I/O 在专用执行路径进行，结果回主线程展示。异步回调使用已经捕获的上下文，不阻塞 Finder 菜单构建。

### 5.5 错误边界

输入边界校验本地文件 URL、目标目录、文件类型和模板存在性。内部服务接收已确定的上下文，不重复猜测默认目录。

区分：用户取消、目标已变化、权限被拒、只读位置、磁盘不足、模板损坏/缺失、Terminal 启动失败、Finder 定位失败。用户取消直接结束；其余错误显示业务描述与下一步，并保留系统错误供诊断。日志使用系统 Logger，完整用户路径按私有数据处理。

### 5.6 终端选择与共享偏好

主应用使用 NSOpenPanel 的应用类型过滤选择任意 `.app`。确认时检查应用包和可执行文件，保存应用标识、显示名和解析后的精确路径；取消不写入，保存失败保留原选择并展示错误。

`TerminalPreferences` 用 Codable Data 写入 `com.yjcdon.MacRight` 偏好域的 `PreferredTerminal`。主应用负责保存，终端启动器在每次请求时同步读取。`TerminalApplication.installedURL()` 统一供设置页图标显示与启动器解析、校验所选应用。

配置缺失使用系统终端；损坏配置明确提示重选，不静默更换应用。已保存的精确路径不可用时提示重新选择，不通过同标识注册项打开另一位置的应用。所选应用须能接收系统目录打开请求，其能力以实际验证为准。

显式选择按保存路径执行，禁用 LaunchServices 的运行中应用替代选项。Bundle ID 是配置元数据，不作为跨进程代码身份安全边界；系统负责验证应用是否可执行。

## 6. 工程、图标与交付

代码目录为 `MacRightApp/`、`FinderExtension/`、`TerminalLauncher/`、`Shared/`、`Resources/`、`docs/`、`scripts/`。

使用 `scripts/build.sh` 调用 Swift 6 编译器构建三个独立可执行文件，最低部署目标为 macOS 13，主应用与扩展的 Bundle ID 分别为 `com.yjcdon.MacRight`、`com.yjcdon.MacRight.FinderExtension`。本地构建默认选择钥匙串中唯一有效的 Apple Development 证书，同时签署主应用、扩展和启动器，保持跨构建身份稳定。其他身份通过 `MACRIGHT_SIGN_IDENTITY` 指定；显式传入 `-` 可生成 ad-hoc 临时构建。证书和私钥由系统钥匙串管理。

应用图标采用 Lucide square-mouse-pointer，白底黑色轮廓。矢量源文件保存在 `Resources/IconSource/`，1024 像素 PNG 保存在 AppIcon 资源目录。构建时通过 sips 和 iconutil 生成标准尺寸 AppIcon.icns，并打包 ISC 许可。

构建、验证、安装和打包分别使用 `scripts/build.sh`、`scripts/verify.sh`、`scripts/install.sh`、`scripts/package.sh`。应用包完全由本仓库源码和资源生成，不从已安装 MacNewFile 复制 storyboard 或 Assets.car。安装先在目标卷暂存并验签，再停止本安装路径下的旧进程、保留旧应用并替换；失败恢复旧路径。替换已安装版本后重新加载正在运行的 Finder，使菜单连接使用当前扩展。Apple Silicon 为首个实机验证架构，Intel 仅在构建并验证后声明支持。

MacRight 采用与参考仓库一致的 GPL v3 许可文件，并记录图标和后续复用资源的来源。与 MacNewFile 使用不同 Bundle ID，可并存；安装验收时明确处理重复右键菜单，由用户在系统设置中停用旧扩展，不自动卸载旧应用。

Finder 同步回调统一通过 `onMainActor` 转交主线程，继续保留菜单目录快照。构建脚本使用同一循环向三个组件复制语言资源。

## 7. 验证与验收证据

先完成权限、上下文、卷发现、Terminal 四项原型验证，再实现各业务能力。默认不新增测试类；采用编译检查、可重复的资源校验和人工场景验收，后续增加自动化测试需单独明确。

重点记录：

- 五类文件可打开；三个 Office 输出与内置模板字节一致，无修复提示。
- 重名、快速连续操作、多实例同时创建均不覆盖；模板哈希保持不变。
- 空白处、单选、多选、侧边栏、包文件、符号链接及中文/空格/引号/美元符号路径。
- 系统访问允许、拒绝、只读卷、目标删除、磁盘错误和复制失败。
- 主程序关闭、Finder/扩展重启、外置卷插拔、睡眠恢复后的菜单行为。
- 工具栏没有入口；应用图标与选定的 Lucide 方框光标一致；日志不公开完整私人路径。

已完成生产核心验证、系统探针、完整应用构建/签名及安装启动；真实界面和 Finder 菜单验收受当前 Mac 锁屏限制，尚未完成。具体证据与未完成项见[验证记录](04-验证记录.md)。
