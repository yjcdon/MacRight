# MacRight 产品方案

状态：首版功能已实现，正在完成实机验收。更新日期：2026-10-26。

## 1. 方案定义

MacRight 是面向 macOS Finder 的轻量右键工具，使用 Swift 重写 MacNewFile 的核心能力：新建常用文件、复制完整路径、在目标目录打开终端。

使用者通过 Finder 或桌面右键完成操作。产品不提供 Finder 工具栏按钮；应用图标直接复用 MacNewFile 的现有 AppIcon。

交付包括公开仓库、Swift 主应用与 Finder 扩展、模板和图标资源、关联方案及可安装版本。功能按项提交，完成自动验证和审查后推送并发布 Release。

## 2. 核心问题与目的

让用户在当前工作位置直接创建可正常打开的文件，并完成路径复制和终端操作，减少切换应用和寻找目录的步骤。

现有实现需要纠正的问题：

- Office 文件由脚本拼装内部 XML，维护成本高，格式完整性依赖手工实现。
- 文件创建、重名处理和结果提示分散，选中文件与目标目录的关系不够清楚。
- 首次启动自动加入登录项，退出应用又关闭扩展，用户难以区分应用与右键功能的运行状态。
- 操作失败主要记录日志，用户难以知道失败原因。

Swift 用于改善实现和维护；用户可感知的收益以文件有效性、位置准确性和错误反馈为准。

## 3. 使用对象与核心场景

面向需要频繁新建文档、复制路径和打开终端的 Mac 用户。

| 场景 | 期望结果 |
| --- | --- |
| 桌面或文件夹空白处右键 | 在当前目录新建文件、复制目录路径、打开终端 |
| 右键一个文件夹 | 对这个文件夹执行操作 |
| 右键一个普通文件 | 复制文件路径；在其所在目录新建文件或打开终端 |
| 多选项目后右键 | 复制全部选中项目的路径；仅在创建位置唯一时提供新建和终端操作 |
| 首次访问尚未授权的位置 | 明确提示授权目录，授权后继续原操作；取消则结束 |

## 4. 产品解决思路

1. **复用真实模板。** Word、Excel、PowerPoint 使用用户提供的三个空白文档作为内置模板。运行时复制资源，不生成 Office 内部结构。文本和 Markdown 创建空文件。
2. **统一右键语义。** 根据右键位置和选中内容确定对象，所有新建操作采用统一的命名、冲突处理和结果反馈。
3. **减少后台负担。** Finder 扩展由系统管理，主应用承担状态查看和启用指引。关闭主应用不影响已启用的右键功能，不自动设置登录启动。
4. **将权限与失败变成可处理的结果。** 需要访问目录时通过系统授权；操作失败说明原因和可采取的行动。

## 5. 核心业务主流程

1. 安装 MacRight，打开应用，按指引在系统设置中启用 Finder 扩展。
2. 在 Finder 或桌面右键，选择新建文件、复制路径或打开终端。
3. 系统确定本次目标；需要目录权限时由用户授权。
4. 执行操作。新建文件成功后在 Finder 中选中它；复制路径和打开终端成功时不额外弹窗。
5. 无法完成时展示原因。再次操作由用户发起，不在后台持续重试。

## 6. 功能与能力骨架

| 编号 | 功能 | 交付能力 |
| --- | --- | --- |
| F-01 | Finder 右键入口 | 覆盖桌面、目录空白处、文件、文件夹和适用的侧边栏目录；不注册工具栏按钮 |
| F-02 | 新建文件 | 支持文本（txt）、Markdown（md）、Word（docx）、Excel（xlsx）、PowerPoint（pptx）五种文件；避免覆盖已有文件；创建后选中文件 |
| F-03 | 复制完整路径 | 单选复制一个路径，多选每行一个路径；目录空白处复制当前目录路径 |
| F-04 | 在目录打开终端 | 打开系统 Terminal 并定位至本次目标目录 |
| F-05 | 扩展状态与启停指引 | 显示扩展是否启用，打开系统扩展管理入口；应用退出与扩展停用分离 |
| F-06 | 目录授权与操作反馈 | 对无访问权限、只读位置、目标消失、模板异常等情况给出可理解的提示 |

主应用采用简体中文和英文界面。首版按 macOS 13 及以上设计，实际支持的系统和架构以完成验证的范围发布。

新建文件功能不包含 Pages、Numbers、Keynote。

## 7. 资源与运行边界

- 三个 Office 模板来自用户桌面的 `untitled.docx`、`untitled.xlsx`、`untitled.pptx`，已保存至仓库；移走桌面原件不影响将来新建文件。
- 公开资源副本清理作者、最后修改者和 WPS 文档标识，保留正文结构、样式、工作表、幻灯片和计算设置。新建时直接复制仓库中的最终模板，不在运行时改写模板内容。
- AppIcon 使用现有项目的原始资源。
- 同名文件自动使用下一个可用名称；原文件和模板不被覆盖。
- 普通本地目录、桌面及可写外置卷是首版验收范围。iCloud Drive、第三方云盘、网络卷、搜索结果和最近使用视图按实测记录支持情况，不将旧项目的兼容性说法直接当作事实。
- 本项目首先面向本地安装及 GitHub 分发；公开仓库创建不代表已发布可安装版本。Finder Sync 对通用右键工具的适用边界见技术方案。

## 8. 交付安排与完成口径

1. **准备阶段：** 建立仓库，保存模板和图标，形成三份关联文档。
2. **实现前验证：** 验证 Finder 菜单上下文、扩展目录授权、外置卷变化、Terminal 打开方式和可重复构建链路。验证失败时先调整技术方案。
3. **实现与验收：** 完成六项能力并验证真实右键操作。模板在 WPS 或对应 Office 应用中打开无修复提示，创建位置正确，重名不覆盖，中文和特殊字符路径可用，失败有明确提示。

授权能力和云盘覆盖属于待实测的技术边界，不以静态检查通过代替功能验收。
